# Irasutoya Doc

このスキルは、スライドやドキュメントを **「いらすとや」（https://www.irasutoya.com）のイラストで統一された HTML** として書き出すためのものです。通常なら SVG 図解や絵文字で表現する箇所を、すべて「いらすとや」の画像に置き換えます。

いらすとやは Blogger 製サイトのため、同梱スクリプトが **Blogger 公開フィード API** で画像を検索・取得します（HTML スクレイピングはしません）。CSS / スタイルはスキル同梱のテンプレートに固定されており、HTML の組み立てはサブエージェントに委任します。

## 1. 発動条件と非発動条件

**発動するとき**（以下のいずれかをユーザーが明示的に指示したターンのみ）
- 「いらすとやでスライド / 資料 / ドキュメントを作って」
- 「irasutoya-doc で」「いらすとや資料にして」
- 「この内容をいらすとやのイラスト付きでまとめて」
- 上記に明確に類する表現

**発動しないとき**
- 他スキルからの連鎖発動
- 「スライドを作って」「資料をまとめて」だけのターン（いらすとや指定が無い）
- 調査・質問応答・コード実装だけで完結するターン

迷ったら発動しないでください。「いらすとや」への言及があるかが判断基準です。

## 2. 利用規約ガードレール（最重要）

いらすとや利用規約（https://www.irasutoya.com/p/terms.html）を必ず守ります。

1. **20 点ルール**: 商用利用は 1 つの制作物につき素材 **20 点まで無料**（21 点以上は有償対応が必要）。同じ画像の複数回使用は 1 点とカウント。
   - 資料設計時に **ユニーク画像数を数え、20 点以内に収める**
   - どうしても 21 点以上必要な構成をユーザーが求めた場合は、規約上有償対応となることを伝え、20 点以内への削減か画像の使い回しを提案する
2. **禁止用途**: 公序良俗に反する目的、攻撃的・差別的・性的・過激な内容、素材主体の再配布・販売にあたる依頼は断る（画像だけを大量に集めた「素材集」的な成果物を作らない）
3. **サイトへの配慮**: 検索・ダウンロードは同梱スクリプト経由とし、リクエスト間に待機を入れる（スクリプトが自動で行う）。1 回の資料作成での検索は必要最小限にする
4. クレジット表記は規約上不要だが、テンプレートのフッターに出典（いらすとや）を記載する

## 3. 動作モデル

```
[親 Claude]                             [サブエージェント (general-purpose)]
 │ ① 形式（スライド/ドキュメント）と内容を特定
 │ ② 構成案 + 各所のビジュアルコンセプトを設計
 │ ③ スクリプトで画像検索（JSON で候補一覧を取得）
 │ ④ タイトルを見て画像を選定（≦20点チェック）
 │ ⑤ スクリプトで選定画像を images/ にダウンロード
 │ ⑥ Agent ツールで起動 ─────────────► テンプレ / カタログを Read
 │                                      本文を組み立てて index.html を Write
 │ ⑦ 保存パスだけ受け取る ◄─────────── 戻り値: 保存パス(短文)
 │ ⑧ スクリプトで画像を data URI 埋め込み（自己完結化）
 │ ⑨ ユーザーに保存パスを伝える
```

画像の検索・選定は**親 Claude が行います**（検索結果 JSON は小さく、タイトルによる選定判断が必要なため）。HTML の組み立てと書き出しは**サブエージェントに委任します**（HTML 全文を親会話履歴に残さないため）。

## 4. 親 Claude の手順

### 4.1 形式と内容の特定

- **形式**: 「スライド / プレゼン / 発表資料」→ スライド形式、「ドキュメント / 説明資料 / 読み物」→ ドキュメント形式。曖昧なら内容から判断（発表用ならスライド）
- **内容**: ユーザーがこのターンで提示した文章・ファイル・会話中の合意内容。見当たらなければユーザーに確認

### 4.2 構成案とビジュアルコンセプトの設計

内容をスライド構成（または章構成）に落とし、**各スライド / 章で使う画像のコンセプト**を決めます。

- スライド: タイトル 1 枚 + セクション区切り + コンテンツスライド。1 スライド 1 メッセージ、画像 1〜4 枚
- ドキュメント: 表紙 + 目次 + 章。1 章に画像 1〜3 枚
- **ユニーク画像数はこの時点で概算し、20 点以内に設計する**（同じ概念には同じ画像を使い回す）

### 4.3 スキルファイルの絶対パス解決

参照ファイルはこの SKILL.md と同じディレクトリ配下にあります。

- `scripts/irasutoya_search.py` — 検索・ダウンロード CLI
- `references/keyword-guide.md` — 概念→検索キーワード変換ガイド
- `references/slide-template.html` / `references/doc-template.html` — テンプレート
- `references/components.md` — 本文部品カタログ

解決手順（上から優先）:
1. 環境変数 `CLAUDE_PLUGIN_ROOT` が定義されていれば → `${CLAUDE_PLUGIN_ROOT}/skills/irasutoya-doc/...`
2. SKILL.md 自身の絶対パスから導出 → `<SKILL.md と同じディレクトリ>/...`
3. 最後の手段: `find ~/.claude -path '*irasutoya-doc/scripts/irasutoya_search.py' -print -quit`

### 4.4 出力先の決定

- 配置先: **ユーザー指定を最優先**。指定が無ければ `./docs/irasutoya-YYYY-MM-DD-{slug}/`（無ければ作成）
  - `slug` は kebab-case、英数字とハイフンのみ、最大 40 文字
- HTML: `{出力ディレクトリ}/index.html`、画像: `{出力ディレクトリ}/images/`
- **反復生成時**: 同日同 slug のディレクトリは上書き（ダウンロード済み画像は再利用し、再ダウンロードしない）

### 4.5 画像の検索

`references/keyword-guide.md` を Read してから、ビジュアルコンセプトを検索キーワードに変換し、スクリプトでまとめて検索します。

```bash
python3 {SCRIPT_ABS_PATH} search 会議 サーバー ひらめき --max 8
```

- 出力はキーワードごとの JSON（`title` / `page_url` / `image_url`）
- ヒットしないキーワードはガイドのフォールバック手順で言い換えて再検索（再検索は 1 コンセプトにつき 2 回まで。それでも無ければその箇所は画像なしにする）
- ネットワーク接続先は `www.irasutoya.com` と `blogger.googleusercontent.com` のみ

### 4.6 画像の選定とライセンスチェック

- 検索結果の **タイトルを読んで**、文脈・トーンに合う画像を選ぶ（`（笑顔）` `（真剣）` などのバリエーションに注意）
- 選定した **ユニーク画像数を数え、20 点以内であることを確認**する。超える場合は構成を見直す（2. のガードレール）

### 4.7 画像のダウンロード

選定した画像 URL をまとめてダウンロードします。

```bash
python3 {SCRIPT_ABS_PATH} download URL1 URL2 ... --dir {出力ディレクトリ}/images
```

- 標準出力に保存パスが 1 行ずつ出る。**ファイル名（例: `kaigi_shinken.png`）を控えて 4.8 で使う**
- 失敗した URL は代替候補で 1 回だけリトライ。それでも失敗したらその画像は使わない

### 4.8 サブエージェントへの委任

`Agent` ツールで `general-purpose` サブエージェントを 1 つ起動します。プロンプトは次のテンプレートに揃えてください。

```
あなたは「irasutoya-doc」スキルのレンダリング担当サブエージェントです。
親 Claude のメインコンテキストを汚さないため、HTML の組み立てと書き出しを引き受けます。

## やること
1. テンプレートを Read（絶対パス）: {TEMPLATE_ABS_PATH}
2. コンポーネントカタログを Read（絶対パス）: {CATALOG_ABS_PATH}
3. 下記「資料の構成」に従い、テンプレート内のプレースホルダを置換して本文を組み立てる
4. 本文はカタログの部品だけで組み立てる。画像は下記「使用できる画像」のファイルだけを
   images/{ファイル名} の相対パスで参照する（存在しない画像パスを発明しない）
5. 出力先へ Write: {OUTPUT_PATH}
6. 戻り値は「保存パス（と必要なら 1〜2 行のサマリ）だけ」。HTML 本文は絶対に出力に含めないこと

## プレースホルダ対応
- {{TITLE}} / {{SUBTITLE}} / {{DATE}} / {{AUTHOR}} / {{META}}: 下記メタ情報の通り
- （ドキュメント形式のみ）{{DOC_TYPE}} / {{VERSION}} / {{TOC}}: カタログ B-1 参照
- {{HERO}}: 指定があれば表紙用画像（カタログ参照）、無ければ空文字
- {{SLIDES}} または {{BODY}}: 資料の構成に従って組み立てる

## 制約
- テンプレ内の <style> 領域は改変しない（プレースホルダ部分のみ置換）
- HTML エスケープを徹底。<script>・外部 CDN・インライン style は追加しない
- 資料内容を要約・脚色しない（忠実に構成し直すのは可、内容の改変は不可）
- すべての <img> に alt を付ける
- 最終応答は「保存パス: {OUTPUT_PATH}」のみ

## メタ情報
- TITLE: {TITLE} / SUBTITLE: {SUBTITLE} / DATE: {DATE} / AUTHOR: {AUTHOR}
- （ドキュメント形式のみ）DOC_TYPE: {DOC_TYPE} / VERSION: {VERSION}
- OUTPUT_PATH: {OUTPUT_PATH}

## 使用できる画像（images/ 配下・これ以外を参照しない）
{画像ファイル名と内容（元イラストのタイトル）の一覧}

## 資料の構成（スライドごと / 章ごとに、見出し・本文・使う画像・使う部品を指定）
---
{構成とコンテンツ本文}
---
```

差し込む値:
- `{TEMPLATE_ABS_PATH}` — 形式に応じて `slide-template.html` または `doc-template.html` の絶対パス
- `{構成とコンテンツ本文}` — 4.2 の構成案。スライド / 章ごとに「見出し・伝えたい内容・使う画像ファイル名・推奨部品（A-3 など）」を書く

### 4.9 自己完結化（画像の埋め込み）

サブエージェントの完了後、**必ず** HTML 内の `images/` 相対参照を data URI に変換します。

```bash
python3 {SCRIPT_ABS_PATH} inline {OUTPUT_PATH}
```

理由: プレビューパネル・チャット添付・単体ファイル共有など、隣の `images/` ディレクトリが一緒に配信されない環境では相対参照の画像が表示されないため。埋め込み後は HTML 1 ファイルだけでどこでも表示できます。

- `images/` ディレクトリは削除しない（反復生成時の再利用のため）
- 出力に `ERROR: 画像ファイルが見つかりません` が出た場合は、サブエージェントが存在しない画像パスを参照している。4.8 を修正して再実行する

### 4.10 戻り値の取り扱いと報告

ユーザーには以下を伝えます。

> `./docs/irasutoya-2026-07-08-xxx/index.html` に書き出しました（画像 N 点 / いらすとや規約の 20 点以内・画像埋め込み済みで単体ファイルとして共有可）。ブラウザで開いて確認、PDF にする場合は印刷（Cmd+P）から「PDF に保存」してください。

## 5. 反復的な修正への対応

- 文言・構成の修正のみ → 画像は再検索せず、4.8 のサブエージェント起動だけ再実行（同パス上書き）
- 画像の差し替え依頼（「このイラスト変えて」）→ 該当コンセプトだけ 4.5〜4.7 を再実行してから再組み立て
- 画像を追加する修正では、その都度ユニーク画像数の 20 点チェックを再実施
- **再生成のたびに 4.9 の埋め込み（inline）も必ず再実行する**（サブエージェントは `images/` 相対参照で書き出すため）

## 6. 禁止事項

- **SVG 図解・絵文字・いらすとや以外の画像で代替すること**(このスキルの趣旨に反する。見つからない場合は画像なしにする)
- 親 Claude が自分でテンプレートを Read して HTML を Write すること（必ずサブエージェント経由）
- サブエージェントの戻り値として HTML 全文を親会話に持ち帰ること
- フィード API 以外の方法でのサイトアクセス（HTML スクレイピング、一括クロール）
- ユニーク画像 21 点以上の商用資料を無警告で作ること
- いらすとや画像の再配布にあたる成果物（素材集・画像アーカイブ）を作ること
- ユーザーが明示指示していないのに先回りで発動すること

## 7. 使う場面

- 社内発表・勉強会・提案のスライドを親しみやすいトーンで作りたい
- 非エンジニア向けの説明資料を、図解の代わりにイラストで分かりやすくしたい
- SVG や絵文字ではなく、統一感のある「いらすとや」テイストの資料にしたい

### 例

良い例:
> ユーザー: 「この障害対応フローをいらすとやでスライドにして」
>
> アシスタント:
> （構成設計 → `search 障害 監視 復旧 報告` → タイトルで選定・8 点 → `download ... --dir ./docs/irasutoya-2026-07-08-incident-flow/images` → サブエージェントで index.html 組み立て）
> 「`./docs/irasutoya-2026-07-08-incident-flow/index.html` に書き出しました（画像 8 点）」

悪い例（代替画像の使用）:
> 検索でヒットしなかった概念に、絵文字や SVG アイコンを埋め込む。
> 問題: 「すべていらすとやで統一する」というスキルの趣旨に反する。画像なしで構成する。

悪い例（ライセンス無視）:
> 30 スライドに 25 種類の画像を使った商用提案資料を無警告で生成する。
> 問題: いらすとや規約では 21 点以上の商用利用は有償。20 点以内に設計し直すか、ユーザーに規約を伝えて判断を仰ぐ。
