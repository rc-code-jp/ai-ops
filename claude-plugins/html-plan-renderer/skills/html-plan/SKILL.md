# HTML Plan

このスキルは、合意済みの実行プランを **読みやすい HTML ファイル** として `./plans/` 配下に書き出すためのものです。Markdown より目次・要点・ファイル一覧・検証手順を視覚的に追えるようにすることが目的です。

**ユーザーは生成された HTML を見ながら、質問・修正依頼・確認プロンプトを繰り返します。大規模リファクタのプランにも使われます。** したがって反復生成と長大プランに耐えるよう、HTML の組み立てはサブエージェントに委任します。

## 1. 発動条件と非発動条件

**発動するとき**(以下のいずれかをユーザーが明示的に指示したターンのみ)
- 「HTML でプランを出して / 書き出して / 保存して」
- 「html-plan で」「html-plan 発動」
- 「いまの計画を HTML にして」「プランを HTML ファイルにして」
- 上記に明確に類する表現

**発動しないとき**(以下では絶対に発動しない)
- Plan Mode を終了した直後の自動連動
- 他スキル(`rikai-implement` など)からの連鎖発動
- ユーザーが「プランを立てて」「計画して」と言っただけのターン(プラン提示は Markdown のままで良い)
- 調査・読み取り・質問応答だけで完結するターン

迷ったら発動しないでください。ユーザーが明示的に指示したかどうかが唯一の判断基準です。

## 2. 動作モデル(委任型)

このスキルは **親 Claude → サブエージェント** の二段構成で動きます。

```
[親 Claude]                       [サブエージェント (general-purpose)]
 │ ① 最新の合意プランを特定
 │ ② メタ情報(repo, branch, 日付)を取得
 │ ③ ファイル名を決定
 │ ④ Agent ツールで起動 ─────────► プロンプト受領
 │                                 │ ⑤ template.html を Read
 │                                 │ ⑥ プレースホルダ置換
 │                                 │ ⑦ ./plans/... へ Write
 │ ⑧ 保存パスだけ受け取る ◄────── 戻り値: 保存パス(短文)
 │ ⑨ ユーザーに保存パスを伝える
```

委任する理由:
- 生成 HTML 全文(数 KB 〜 数十 KB)を親会話履歴に残さないため
- 反復的な再生成(質問→プラン更新→再 HTML 化)で親コンテキストが累積しないため
- 大規模リファクタの長大なプランでもメイン推論を圧迫しないため

**親 Claude がやってはいけないこと**: 自分で `template.html` を Read したり、自分で `Write` を呼んだりしないでください。必ずサブエージェントに委任します(理由: そうしないと HTML 全文が親履歴に残るため)。

## 3. 親 Claude の手順

### 3.1 入力(合意済みプラン)の特定

次の優先順位で「現在のプラン」を特定します。
1. 直前のターンに `ExitPlanMode` で承認されたプラン本文
2. 会話中で直近に合意した実装計画(要点ブロック、TodoWrite の内容、ユーザーが OK を出した提案など)
3. それも見当たらない場合は、ユーザーに「どのプランを HTML 化しますか?」と 1 ターン 1 判断で確認

### 3.2 メタ情報の取得

- リポジトリ名: `git remote get-url origin` の末尾(`org/repo`)、取れなければ空
- ブランチ名: `git branch --show-current`、取れなければ空
- 日付: 本日(`YYYY-MM-DD`)

### 3.3 ファイル名規則

- 配置先: 作業中リポジトリのルート相対 `./plans/`(無ければ作成)
- ファイル名: `plan-YYYY-MM-DD-{slug}.html`
  - `slug` は kebab-case、英数字とハイフンのみ、最大 40 文字
  - 日本語タイトルは英訳または音写して kebab-case 化
- **反復生成時の上書きルール**: 同一日に **同じ slug** のファイルがあれば **上書き** する(プランの修正→再生成のため)。slug が変われば別ファイルとして併存。
- 明示的に「別ファイルとして残して」と言われた場合のみ `-2`, `-3` を末尾に付与

### 3.4 サブエージェントへの委任

`Agent` ツールで `general-purpose` サブエージェントを 1 つ起動します。プロンプトは次のテンプレートに揃えてください。

```
あなたは「html-plan」スキルのレンダリング担当サブエージェントです。
親 Claude のメインコンテキストを汚さないため、HTML の組み立てと書き出しを引き受けます。

## やること
1. テンプレートを Read:
   {PLUGIN_ROOT}/claude-plugins/html-plan-renderer/skills/html-plan/references/template.html
2. 下記「プラン本文」から各セクションを抽出し、テンプレート内のプレースホルダを置換
3. 出力先へ Write: {OUTPUT_PATH}
4. 戻り値は「保存パス(と必要なら 1〜2 行のサマリ)だけ」。HTML 本文は絶対に出力に含めないこと

## プレースホルダ対応
- {{TITLE}}                プラン主題を 1 行で
- {{GENERATED_AT_ISO}}     ISO 8601(例: 2026-05-11T10:30:00+09:00)
- {{GENERATED_AT}}         人間向け表記(例: 2026-05-11 10:30)
- {{REPO}}                 {REPO} を埋める(空なら "-")
- {{BRANCH}}               {BRANCH} を埋める(空なら "-")
- {{TOC}}                  <li><a href="#anchor">章タイトル</a></li> を必要数
- {{SUMMARY_WHAT}}         要点: 何を
- {{SUMMARY_WHY}}          要点: なぜ
- {{SUMMARY_HOW}}          要点: どう
- {{SUMMARY_SIDE_EFFECTS}} 要点: 副作用と影響範囲
- {{SUMMARY_OUT_OF_SCOPE}} 要点: スコープ外
- {{CONTEXT}}              背景/目的の本文(段落タグで)
- {{FILES_TABLE}}          <tr><td>path</td><td class="op" data-op="add|edit|delete">操作</td><td>概要</td></tr> を必要数
- {{STEPS}}                <li><strong>見出し</strong><div class="step-goal">目的/完了条件</div><p>詳細</p></li>
- {{VERIFICATION}}         <li>検証項目</li>(チェックボックス記号はテンプレ側 CSS が付ける)
- {{META}}                 "skill: html-plan / branch: ..." 等の補足

## 制約
- テンプレ内の <style> や <script> 領域は改変しない(プレースホルダ部分のみ置換)
- HTML エスケープを徹底(<, >, &, ", ' を実体参照に)
- 外部 CDN や JS は追加しない
- 抽出時にプラン内容を要約・脚色しない(忠実に転記)
- 出力ディレクトリが無ければ作成
- 最終応答は「保存パス: ./plans/xxxx.html」のみ(HTML 全文を返さない)

## メタ情報
- REPO: {REPO}
- BRANCH: {BRANCH}
- OUTPUT_PATH: {OUTPUT_PATH}

## プラン本文(忠実に HTML 化する対象)
---
{PLAN_BODY}
---
```

差し込む値:
- `{PLUGIN_ROOT}` — このプラグインが置かれているリポジトリのルート絶対パス(または相対パス)
- `{REPO}` / `{BRANCH}` / `{OUTPUT_PATH}` — 3.2 / 3.3 で求めた値
- `{PLAN_BODY}` — 3.1 で特定した合意済みプラン本文を **そのまま** 貼る(要約しない)

### 3.5 戻り値の取り扱い

サブエージェントは「保存パス」と短いサマリだけ返してきます。親 Claude はこれをユーザーに伝えるだけにしてください。

良い報告例:
> `./plans/plan-2026-05-11-add-html-plan-skill.html` に書き出しました。ブラウザで開いてご確認ください。

悪い報告例:
- 生成された HTML の中身を会話に貼り直す
- プラン本文を再掲する
- サブエージェントが返した説明を長々と転記する

## 4. 反復的なプラン修正への対応

ユーザーは HTML を見ながら以下を行うことが想定されます。

- 「ここの章を書き換えて」「ステップ 3 を分割して」など部分修正
- 「副作用に X を追加して」など要点ブロックの修正
- 「もう一度 HTML にして」と再生成

このとき親 Claude は:
1. まず会話上でプラン本文を更新する(要点ブロックや TodoWrite を最新化)
2. 「もう一度 HTML にして」と言われたら、最新のプラン本文を持って 3.4 のサブエージェント起動を再実行
3. 同日同 slug のファイルは上書きする(3.3 の上書きルール)

サブエージェントは毎回新規に起動して構いません(状態を持たない)。親会話には HTML 全文が残らないため、何度反復しても親コンテキストは膨れません。

## 5. 大規模リファクタへの配慮

長大なプランでも 1 枚物の HTML として出力します(初期版)。サブエージェント側でテンプレ置換するため、親には HTML 全文が戻りません。

将来必要になったら章単位の分割出力(`plan-...-overview.html` + `plan-...-module-foo.html` …)も検討しますが、最初は導入しません(早すぎる抽象化を避けるため)。ユーザーから「分割して出して」と明示要望が出た時点で追加します。

## 6. スタイル方針(テンプレート側で守る)

- `<style>` は `<head>` 内にインライン。外部 CSS / CDN は使わない
- 外部 JS、`<script>` タグは一切埋め込まない
- フォントは `system-ui, -apple-system, "Segoe UI", "Hiragino Sans", "Yu Gothic", sans-serif`
- `body { max-width: 760px; margin: 0 auto; line-height: 1.7; }`
- `@media (prefers-color-scheme: dark)` でダークパレットに切り替え
- `@media print` で目次 `<nav>` を非表示にし、A4 印刷 / PDF 出力に耐える
- 色数は抑える(本文 / 強調 / 罫線 / 背景の 4 色程度)

## 7. 禁止事項

- **親 Claude が直接 `template.html` を Read したり、`Write` で HTML を書き出すこと**(必ずサブエージェント経由)
- サブエージェントの戻り値として HTML 全文を親会話に持ち帰ること
- `./plans/` 以外への HTML 書き込み
- HTML 内への `<script>` 埋め込み、`onload` などのイベントハンドラ
- 外部 CDN(Google Fonts、Tailwind CDN、Mermaid CDN など)への参照
- Plan Mode 終了や他スキル発動に紐づく自動発動
- ユーザーが明示指示していないのに先回りで HTML 出力すること
- プラン内容を勝手に書き換える / 追加で考察を入れる(忠実な可視化に徹する)

## 8. 使う場面

- Plan Mode で合意したプランを後でブラウザでレビューしたい
- 非エンジニアや別チームにプラン内容を共有したい
- 印刷 / PDF として保存しておきたい
- 長大なプラン(大規模リファクタ等)を目次付きで眺めたい
- プランを反復的に修正しながら HTML を更新したい

良い例:
> ユーザー: 「いまのプランを HTML で出して」
>
> アシスタント:
> (Agent ツールで general-purpose サブエージェントを起動。プロンプトに 3.4 のテンプレを使い、プラン本文を埋め込む)
>
> サブエージェント: `保存しました: ./plans/plan-2026-05-11-refactor-auth-module.html`
>
> アシスタント:
> 「`./plans/plan-2026-05-11-refactor-auth-module.html` に書き出しました。ブラウザで開いてご確認ください。」

良い例(反復修正):
> ユーザー: 「ステップ 2 に DB マイグレーションを追加して、もう一度 HTML にして」
>
> アシスタント:
> (会話上でプラン本文を更新 → 再びサブエージェントを起動 → 同 slug を上書き)
> 「同じパスに上書きしました: `./plans/plan-2026-05-11-refactor-auth-module.html`」

悪い例(直接 Write):
> ユーザー: 「HTML で出して」
>
> アシスタント: (自分で `template.html` を Read して置換し、自分で Write を呼ぶ)
>
> 問題: HTML 全文が親会話履歴に残り、その後の反復で累積する。大規模プランや繰り返し編集でメインコンテキストを圧迫する。

悪い例(自動発動):
> ユーザー: 「プランを立てて」
>
> アシスタント: (Markdown でプランを提示したあと、聞かれていないのに HTML ファイルも生成する)
>
> 問題: ユーザーが明示指示していないのに発動しており、本スキルの禁止事項に該当。
