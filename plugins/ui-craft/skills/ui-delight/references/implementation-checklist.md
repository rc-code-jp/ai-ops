# Implementation Checklist

実装時と実装後の確認観点です。

## タイポグラフィと色

- 表情のあるフォントを使う。Inter、Roboto、Arial、system の安易なデフォルトに寄せない
- 書体は原則 2 種までに抑える
- 色の方向性を先に決め、CSS 変数で管理する
- `--background`、`--surface`、`--text-primary`、`--text-muted`、`--accent` などのトークンを先に置く
- 紫ベースの白背景や、なんとなく暗色テーマに逃げるデフォルトを避ける

## 背景と余白

- 単色ベタ背景に頼らず、グラデーション、画像、質感、微細なパターンで空気を作る
- クロームを足す前に、余白、整列、サイズ差、トリミング、コントラストで解決する
- テキスト列は細めに保ち、落ち着いた領域にアンカーする

## カードと装飾

- デフォルトはカードなし
- ヒーローではカードを使わない
- カードは、その枠自体が操作や理解に必要なときだけ許可する
- 枠線、影、背景、角丸を外しても成立するなら、それはカードにしない
- pill の群れ、stat strip、icon row、boxed promo、schedule snippet のような clutter を増やさない

## モーション

- モーションはノイズではなく、存在感と階層のために使う
- 視覚主導の画面では、2〜3 個の意図的なモーションを最低限入れる
- 固定要素や浮遊要素は、どの画面幅でも本文や CTA を塞がない安全な位置に置く

## React 実装

- チームで使われているなら `useEffectEvent`、`startTransition`、`useDeferredValue` などの現代的なパターンを使う
- `useMemo` や `useCallback` は既存コードで明確に使われている場合を除き、デフォルトで追加しない
- リポジトリの React Compiler 方針があるならそれに従う

## 検証

実装後は、少なくとも次を自分で確認します。

- デスクトップとモバイルの両方で崩れていないか
- 固定ヘッダーや浮遊要素が本文や CTA を隠していないか
- ファーストビューが情報過多になっていないか
- 画像が主役として機能しているか
- ブランド階層が明確か
- モーションがノイズではなく意味を持っているか

Playwright や同等の確認手段が使えるなら、表示確認、主要導線、複数ビューポート確認まで行います。
