# Agents Md Improver

AGENTS.md と CLAUDE.md を、常時読み込ませる価値がある制約と作業前提だけに絞り、詳細手順を適切な skill や別ドキュメントへ分離する。

## 重要方針

- 常時読み込み指示は短く、具体的で、検証可能に保つ
- 個人設定、プロジェクト設定、サブディレクトリ設定の責務を混ぜない
- 長い手順や特定タスクのレビュー観点は skill、references、docs へ逃がす
- Codex と Claude Code の差分は必要な箇所だけに限定し、共通化できる指示は共通指示へ寄せる
- 指摘は、実行ブレ、誤読込、保守不能、権限や安全性のリスクを優先する

## 対象

- `AGENTS.md`
- `CLAUDE.md`
- AGENTS.md や CLAUDE.md から `@` 参照される補助ドキュメント
- リポジトリ内の関連する agent / skill / plugin 設定

## 手順

### 1. 対象ファイルを特定する

入力: ユーザー指定のパス、またはリポジトリ内の指示ファイル候補
出力: レビュー対象一覧

- `AGENTS.md` と `CLAUDE.md` の有無を確認する
- `CLAUDE.md` が `@AGENTS.md` のような参照だけを持つ場合は、参照先を主対象として扱う
- サブディレクトリに同名ファイルがある場合は、スコープ差分も確認する
- SKILL.md や custom agent 定義が指定された場合は対象外であることを伝え、適切なスキルへ切り替える

### 2. 現状の役割を要約する

入力: 対象ファイル本文
出力: 現状の責務要約 2〜4 文

- 常時守るルールなのか、特定作業の手順なのかを分ける
- Codex / Claude Code / 共通指示のどれに属するかを整理する
- 指示の読み込み範囲と優先順位を確認する

### 3. 詳細チェックリストを読む

入力: 対象ファイルと `references/review-checklist.md`
出力: 重要度つき findings

- `references/review-checklist.md` の観点で、役割分離、具体性、検証可能性、スコープ設計、衝突、保守性を確認する
- 参照ファイルを含めた合計量が大きい場合は、毎回読むべき内容と必要時だけ読む内容へ分ける
- APM 化できる共通指示、tool 固有に残すべき指示、削るべき重複を分類する

### 4. 改善案を作る

入力: findings
出力: 具体的な編集案またはパッチ方針

- 曖昧語は具体的な行動、条件、コマンドへ置き換える
- 長い手順は skill、references、docs へ分離する
- Codex と Claude Code で同じ内容を二重管理している場合は、片方を参照または APM 管理対象へ寄せる
- 個人設定や環境依存の内容は repo 指示から外す

### 5. 結果を報告する

入力: レビュー結果または編集差分
出力: 重要度順の報告

- findings は重大度順に出す
- 各 finding には、対象箇所、問題、影響、改善案を含める
- 編集した場合は、変更ファイルと検証内容を簡潔に示す
- 未検証の項目や、APM CLI が必要で確認できない項目があれば明示する

## 出力形式

レビューのみの場合:

```md
## Findings

- 重大度: 高
  対象: `AGENTS.md`
  問題: ...
  影響: ...
  改善案: ...

## 総合評価

A〜D の評価と理由を 2〜4 文で示す。
```

編集まで行った場合:

```md
変更内容:
- `AGENTS.md`: ...
- `CLAUDE.md`: ...

検証:
- ...
```
