# codex-skill-improver 自身のテスト設計

## 発火テスト

### 発火すべき依頼（5 件）

1. 「この SKILL.md を Codex 向けに見直して」
2. 「スキルが Codex で暗黙発火しないので改善して」
3. 「Claude 向けのスキルを Codex に移植したい」
4. 「Codex Skills の公式ベストプラクティスに合わせて」
5. 「このスキルの description 境界を調整して」

### 発火すべきでない依頼（5 件）

1. 「このプルリクエストをレビューして」→ コードレビュー / PR レビュー
2. 「AGENTS.md を改善して」→ agents-md-improver
3. 「custom agent の TOML を見直して」→ codex-subagent-improver
4. 「README.md を読みやすくして」→ 一般ドキュメント改善
5. 「新しいスキルを 1 から設計して」→ skill-creator 系の作成タスク

## 機能テスト

### 正常系

#### ケース 1: `description` が能力紹介で終わっている
入力: `description: スキルを改善する。`
期待出力:
- 重大度「高」: 暗黙発火の境界が成立していない
- 「いつ使うか」と「使わない場面」を含む改善案が出る

#### ケース 2: 1 スキル 1 責務を破っている
入力: SKILL.md で「スキル改善」「AGENTS.md 改善」「コードレビュー」を同時に扱う
期待出力:
- 重大度「高」: 責務過多
- 分割案または対象縮小案が出る

#### ケース 3: 手順はあるが入出力が不明
入力: ステップが箇条書きだけで、各段階の成果物が不明な SKILL.md
期待出力:
- 重大度「中」以上: 実行順序の再現性不足
- 入力 / 出力つき手順への修正案が出る

#### ケース 4: 高品質な Codex スキル
入力: 発火境界、責務、段階的開示、補助ファイル構成が適切な SKILL.md
期待出力:
- findings なし、または軽微な改善のみ
- 残るリスクや未検証項目が明示される

### エラー系

#### ケース 5: YAML フロントマターが壊れている
入力: `---` デリミタ欠落
期待出力:
- 構文エラーを報告する
- `scripts/validate_frontmatter.sh` の実行または修正案が示される

#### ケース 6: SKILL.md が存在しない
入力: `references/` だけがあるディレクトリ
期待出力:
- スキルとして不完全だと報告する
- 必須ファイルとして `SKILL.md` の追加を求める

## ベースライン比較

| 指標 | スキルなし（手動レビュー） | スキルあり |
|---|---|---|
| Codex 公式仕様への整合 | レビュアー依存で漏れやすい | 毎回同じ観点で確認 |
| `description` の発火境界評価 | 口頭指摘に留まりやすい | 暗黙発火前提で修正文まで出る |
| 役割分割の判断 | 感覚的になりやすい | 1 スキル 1 責務で整理できる |
| 文脈量の最適化 | 背景説明が肥大化しやすい | 段階的開示を前提に整理できる |
