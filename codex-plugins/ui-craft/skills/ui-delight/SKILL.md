# UI Delight

このスキルは、機能の有無よりも、構図、視線誘導、ブランド表現、画像、余白、モーションで品質が決まるUI実装に使います。

目標は、意図のある、上質で、現在の水準に達したUIを実装することです。
デフォルトは「大きな一つのアイデア」「強い視覚アンカー」「短いコピー」「厳密な余白」「少数の印象的なモーション」です。

## 使う場面

- 新規ランディングページを作る
- ブランドサイトやキャンペーンページを作る
- 見た目の完成度が重要なアプリUIやデモUIを作る
- 「いい感じ」ではなく、明確なアートディレクションが必要
- 既存画面のリデザインや磨き込みを行う

次のような場合はこのスキルを弱めるか使わないでください。

- 管理画面や業務UIで、装飾より情報密度と操作効率が最優先
- 既存のデザインシステムやブランド規約に厳密準拠すべき
- まず機能だけ通せばよく、見た目の作り込みが主目的ではない

## 作業開始時の進め方

実装前に、次の3点を必ず短い箇条書きで明示してから着手します。

- visual thesis: ムード、素材感、温度感、密度を1文で定義する
- content plan: hero、support、detail、final CTA の流れを決める
- interaction thesis: ページや画面の印象を変える 2〜3 個のモーションを決める

この3点を出さずに実装へ入らないでください。
実装後は、できあがったUIが最初に定義した 3 点と矛盾していないかを確認してください。

各セクションには、1つの役割、1つの主見出し、1つの主要メッセージだけを持たせます。
セクションの責務が曖昧なら、追加するのではなく削る方向で調整します。

## ハードルール

- 最初のビューポートは、1つの構図として読めるようにする
- ブランド名またはプロダクト名をヒーローレベルの信号にする
- デフォルトはカードなし。カードは操作や理解に必要なときだけ許可する
- 表情のあるフォント、意図のある背景、明確な色の方向性を先に決める
- 画像は主役として機能させる。抽象背景だけで主ビジュアルを済ませない
- モーションはノイズではなく、存在感と階層のために使う
- 既存サイトやデザインシステムがある場合は、それを壊さずに品質だけ上げる

## 実装方針

- まず構図から決め、後で部品に分解する
- 先にデザイントークンを置き、あとから場当たり的に色を足さない
- 実データや実文脈があるなら、それを使って構造とコピーを決める
- プレースホルダー文言で逃げず、画面の物語を成立させる

React を使う場合は次を優先します。

- チームで使われているなら `useEffectEvent`、`startTransition`、`useDeferredValue` などの現代的なパターンを使う
- `useMemo` や `useCallback` は既存コードで明確に使われている場合を除き、デフォルトで追加しない
- リポジトリの React Compiler 方針があるならそれに従う

## 参照ファイル

用途に応じて必要なものだけ読んでください。

- ブランド訴求、ヒーロー構図、最初の画面の印象づくりが主課題なら [references/landing-pages.md](references/landing-pages.md)
- 継続操作、情報密度、作業効率、画面内の読みやすさが主課題なら [references/app-ui.md](references/app-ui.md)
- トークン、モーション、レスポンシブ確認、検証観点: [references/implementation-checklist.md](references/implementation-checklist.md)

迷う場合は次で判定します。

- 最初の画面でブランドや世界観を強く伝える必要があるなら landing-pages を優先する
- ユーザーが画面上で作業を続けることが主目的なら app-ui を優先する
- 1つの画面に両方の要素がある場合でも、画面の主目的を1つに決め、主目的側の参照を優先する

## 禁止事項

- generic で過剰に組まれたレイアウトに戻ること
- ヒーローをカードや小要素の集合にすること
- 何となくカードを量産すること
- 画像の代わりに抽象背景だけで主役を済ませること
- 複数の要点を同じセクションに詰め込むこと
- 既存の視覚言語があるのに、別物のデザインへ破壊的に置き換えること

## 優先順位

迷ったら次の順で優先します。

1. 構図の強さ
2. ブランドと視覚階層
3. 画像または実体のある視覚アンカー
4. 余白、タイポグラフィ、色の一貫性
5. 最低限で効くモーション
6. コンポーネント数の少なさ

部品を足して解決するより、削って強くする方向を常に優先してください。
