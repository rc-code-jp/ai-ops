# Deliberate With Agents

## 責務を限定する

- 2体のサブエージェントによる独立分析、1回の相互批評、親エージェントによる統合だけを行う。
- サブエージェントの多数決を結論として扱わず、根拠の品質、反証への耐性、制約との整合性で判断する。
- このスキルの手順として、審議中のファイル変更、外部への書き込み、その他の状態変更を禁止する。親タスクが書き込み可能な場合、この禁止は指示上の制約であり、技術的な権限制御ではない。
- 実装依頼も含まれる場合は審議を先に完了し、親エージェントが上位指示とユーザーの権限を再確認してから別フェーズで扱う。
- 適用される `AGENTS.md`、システム指示、ユーザー指示を常に優先する。

## 1. 案件票を作る

次の項目を短く整理する。

- 検討対象
- 判断したいこと
- 対象外
- 判断基準と制約
- 確認済みの事実
- 未確認事項

会話全文をそのまま渡さず、判断に必要な依頼、制約、生資料だけを抽出する。秘密情報や無関係な文脈をサブエージェントへ複製しない。案件票だけで各役が判断できる自己完結した内容にする。

## 2. 独立分析を依頼する

親エージェントから、同一の案件票を使って次の2体を並行起動する。どちらかの初稿を待ってから他方を起動してはいけない。利用可能な場合は `fork_turns: "none"` を使い、必要な案件票と生資料の参照だけを個別の依頼に含める。

各サブエージェントには、読み取り系の調査だけを許可し、状態変更、権限昇格の要求、追加のサブエージェント起動を禁止する。

### 構成・証拠役

次を返すよう依頼する。

- 現時点の推奨
- 主要な根拠と出典
- 置いた前提
- 代替案と不採用理由
- 最大の失敗条件
- 結論を変える条件

### 反証役

構成役の初稿を見せず、同じ案件票から独立して次を返すよう依頼する。

- 独立した暫定結論
- 隠れた前提と反例
- 証拠不足や制約違反
- 重大な失敗条件と影響
- 見落とされやすい代替案
- 結論を変える条件

両者に、事実、推測、提案を区別させる。可能な範囲でファイルパスと行番号、公式文書のURL、実行結果などを根拠に付けさせる。

## 3. 相互批評を1回だけ行う

両方の初稿が揃うまで相互批評を開始しない。親エージェントは、各初稿の重大な主張に `A1`、`B1` のようなIDを付け、`主張 / 根拠 / 出典 / 前提 / 不確実性` の形式へ正規化する。重大な反例や不確実性を省略せず、要約で意味を変えない。

両者の逐語回答ではなく、この構造化した主張を親エージェントが相互に中継する。

各役に次を返すよう依頼する。

- 相手の主張IDごとの採用、部分採用、不採用
- 判断理由と追加の根拠
- 初期結論の維持、修正、撤回
- 未解決の争点

各役への相互批評依頼は1回で終了し、追加の再反論を行わない。新しい根拠が出た場合は親エージェントが確認し、結論を変えた理由または未解決事項として記録する。

## 4. 親エージェントが統合する

次の順で評価する。

1. 一次情報、公式情報、実行結果を優先する。
2. 根拠の鮮度と対象への直接性を確認する。
3. 反証を受けて維持された主張と、修正または撤回された主張を分ける。
4. 重大な未解決事項を合意で消さず、判断への影響を示す。
5. 証拠が不足する場合は無理に決めず、判断を保留する。

変更可否を判断する場合は、次のいずれかを使用する。

- 変更を推奨
- 条件付きで変更を推奨
- 変更を推奨しない
- 情報不足のため判断保留

この判断を、ユーザーによる実行許可や組織上の承認として扱わない。

## 5. 結果を返す

生の対話ログや内部の思考過程を出さず、次を簡潔に返す。

1. 結論
2. 主要な根拠と出典
3. 重要な反証と、それによって変わった点
4. 未解決事項
5. 次のアクションと変更権限の状態

最終結果でも事実、推測、提案を区別する。出典を確認できない重要な主張は、根拠ではなく未解決事項へ移す。

最後に、起動に成功した役割、完了した段階、相互批評の成否、停止理由を1文で示す。変更権限の状態には、読み取り専用が環境で強制されているか、指示上の制約だけかも記載する。

## 縮退を明示する

初稿または相互批評で失敗した役だけを最大1回再試行する。初稿を2体分取得できなければ相互批評を行わず、取得できた初稿と親エージェントによる単独の反証レビューへ縮退する。相互批評の片側だけを取得できた場合は、完了した結果だけで統合し、相互批評が部分的だったことを明示する。

利用できなかった役、失敗した段階、再試行回数を報告する。2体の独立分析や相互批評を完了していない場合は、完了したように表現しない。

サブエージェントは親の権限設定を継承する。技術的な読み取り専用が必須の案件では、親タスクが読み取り専用であることを確認してから起動する。確認できなければ審議を開始せず、必要な権限設定をユーザーへ伝える。
