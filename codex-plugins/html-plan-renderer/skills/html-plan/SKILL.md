# HTML Plan

合意済みの実行プランを **読みやすい HTML ファイル** として `./plans/` 配下に書き出すスキル。目次・TL;DR・メタチップ・ファイル変更表・必読ブロック・折りたたみステップを備える。

ユーザーは生成された HTML を見ながら、質問・修正依頼・確認プロンプトを繰り返す。大規模リファクタのプランにも使われる。反復生成と長大プランに耐えるため、HTML の組み立ては同梱の Python スクリプト(`scripts/render_plan.py`)に委ね、生成 HTML 全文は Codex の会話履歴に残さない。

プレースホルダ仕様の詳細は `references/placeholders.md` を参照する。

## 1. 発動条件と非発動条件

発動するとき(以下のいずれかをユーザーが明示的に指示したターンのみ):

- 「HTML でプランを出して / 書き出して / 保存して」
- 「html-plan で」「html-plan 発動」
- 「いまの計画を HTML にして」「プランを HTML ファイルにして」
- 上記に明確に類する表現

発動しないとき(以下では絶対に発動しない):

- プランを立てた直後の自動連動
- 他スキルからの連鎖発動
- ユーザーが「プランを立てて」「計画して」と言っただけのターン(プラン提示は Markdown のままで良い)
- 調査・読み取り・質問応答だけで完結するターン

迷ったら発動しない。ユーザーが明示的に指示したかどうかが唯一の判断基準。

## 2. 手順

### 2.1 合意済みプランを特定する

入力: 直近の会話履歴
出力: HTML 化対象のプラン本文

- 直近に合意した実装計画(要点ブロック、TODO、ユーザーが OK を出した提案など)を特定する
- 直前のターンに承認されたプランがあればそれを優先する
- 見当たらない場合は「どのプランを HTML 化しますか?」とユーザーに 1 ターン 1 判断で確認する

### 2.2 メタ情報を取得する

入力: 作業中リポジトリ
出力: `REPO`, `BRANCH`, 日付(`YYYY-MM-DD`)

- `git remote get-url origin` の末尾を `REPO` とする。取れなければ空文字
- `git branch --show-current` を `BRANCH` とする。取れなければ空文字
- 日付は本日

### 2.3 出力ファイル名を決める

入力: プラン主題、本日日付
出力: `./plans/plan-YYYY-MM-DD-{slug}.html`

- 配置先: 作業中リポジトリのルート相対 `./plans/`(無ければスクリプトが作成する)
- `slug` は kebab-case、英数字とハイフンのみ、最大 40 文字
- 日本語タイトルは英訳または音写して kebab-case 化する
- 反復生成時の上書きルール: 同日同 slug は **上書き** する(プランの修正→再生成のため)。slug が変われば別ファイルとして併存
- ユーザーが明示的に「別ファイルとして残して」と言った場合のみ `-2`, `-3` を末尾に付ける

### 2.4 テンプレートとスクリプトの絶対パスを解決する

入力: 環境変数または SKILL.md の位置
出力: `TEMPLATE_ABS_PATH`, `SCRIPT_ABS_PATH`

解決手順(上から優先):

1. 環境変数 `CODEX_PLUGIN_ROOT` が定義されていれば
   - `TEMPLATE_ABS_PATH = ${CODEX_PLUGIN_ROOT}/assets/template.html`
   - `SCRIPT_ABS_PATH = ${CODEX_PLUGIN_ROOT}/skills/html-plan/scripts/render_plan.py`
2. SKILL.md 自身の絶対パスから導出
   - SKILL.md のディレクトリを `<SKILL_DIR>` とすると、プラグインルートは `<SKILL_DIR>/../..`
   - `TEMPLATE_ABS_PATH = <SKILL_DIR>/../../assets/template.html`
   - `SCRIPT_ABS_PATH = <SKILL_DIR>/scripts/render_plan.py`
3. それも不明な場合のみ最後の手段として `find` で探索する

### 2.5 構造化値の JSON を作る

入力: プラン本文(2.1)、メタ情報(2.2)
出力: 一時 JSON ファイル(例: `/tmp/html-plan-<random>.json`)

- `references/placeholders.md` のキー一覧と書式に従って値を組み立てる
- raw キー(`TOC`, `FILES_TABLE`, `MUST_READ`, `STEPS`, `VERIFICATION`, `CONTEXT`)以外はプレーンテキストで渡す。スクリプト側で HTML エスケープされる
- raw キーは HTML 断片そのものを渡す。値の中の文字列リテラル(プラン本文からの引用)は親 Codex 側で必ず HTML エスケープする
- JSON ファイルは `Write` ツールで書き出す

### 2.6 スクリプトを呼び出す

入力: `TEMPLATE_ABS_PATH`, `SCRIPT_ABS_PATH`, 出力パス、JSON パス
出力: 保存パス(標準出力 1 行)

実行コマンド:

```
python3 <SCRIPT_ABS_PATH> \
  --template <TEMPLATE_ABS_PATH> \
  --output ./plans/plan-YYYY-MM-DD-<slug>.html \
  --values <JSON_PATH>
```

- 標準出力に保存パスが 1 行で印字される。これだけを受け取る
- HTML 全文は標準出力にも応答にも現れない。これがコンテキスト保護のキモ
- 終了コードが 0 以外なら、stderr のエラーをそのままユーザーに報告して中断する

### 2.7 ユーザーに保存パスだけを伝える

入力: スクリプトが返した保存パス
出力: ユーザーへの応答

- 「`./plans/plan-2026-05-12-foo.html` に書き出しました。ブラウザで開いてご確認ください。」とだけ伝える
- HTML 全文、プラン本文の再掲、スクリプトの長い説明は応答に含めない

## 3. 反復的なプラン修正への対応

ユーザーは HTML を見ながら以下を行う想定:

- 「ここの章を書き換えて」「ステップ 3 を分割して」など部分修正
- 「副作用に X を追加して」など要点ブロックの修正
- 「もう一度 HTML にして」と再生成

このとき:

1. まず会話上でプラン本文を更新する(要点ブロックや TODO を最新化)
2. 「もう一度 HTML にして」と言われたら、最新のプラン本文を持って 2.5 と 2.6 を再実行する
3. 同日同 slug のファイルは上書きする(2.3 の上書きルール)

スクリプトは毎回新規に起動して構わない(状態を持たない)。HTML 全文は会話履歴に残らないため、何度反復してもコンテキストは膨れない。

## 4. 出力ルール

- 応答は保存パス(と必要なら 1〜2 行のサマリ)だけ
- 生成 HTML の中身は会話に貼り直さない
- プラン本文を再掲しない
- スクリプトが返したメッセージを長々と転記しない
- 出力先は必ず `./plans/` 配下。リポジトリ外には書かない

## 5. 禁止事項

- 親 Codex が自分で `template.html` を `Read` して置換し、自分で `Write` を呼ぶこと(必ず `scripts/render_plan.py` 経由)
- 生成 HTML 全文を会話に持ち帰ること
- `./plans/` 以外への HTML 書き込み
- HTML 内への `<script>` 埋め込み、`onload` などのイベントハンドラ追加
- 外部 CDN(Google Fonts、Tailwind CDN、Mermaid CDN など)への参照
- プランを立てた直後や他スキル発動に紐づく自動発動
- ユーザーが明示指示していないのに先回りで HTML 出力すること
- プラン内容を勝手に書き換える / 追加で考察を入れる(忠実な可視化に徹する)

## 6. 大規模リファクタへの配慮

長大なプランでも 1 枚物の HTML として出力する(初期版)。スクリプト側でテンプレ置換するため、親 Codex には HTML 全文が戻らない。

将来必要になったら章単位の分割出力も検討するが、最初は導入しない(早すぎる抽象化を避けるため)。ユーザーから「分割して出して」と明示要望が出た時点で追加する。
